This audit distinguishes the originating catalog or observer from the service/file used to retrieve a record. The E-001 file name and the label `TLEs` do not prove a CelesTrak or Space-Track origin. The archived GEO record does establish immediate retrieval from a CelesTrak file held by the Internet Archive; it does not establish its original catalog producer. The stored E-001 files predate this audit. The new E-002 preview adds only a manifest and a browser fetch of existing published files.

[Space-Track's current documentation](https://www.space-track.org/documentation) states blanket approval to transfer or redistribute basic SSA TLE/OMM/SATCAT data when appropriately cited. That statement does not resolve independent observer terms for the SeeSat-L sets. For additional historical CelesTrak elements, use [CelesTrak's historical request route](https://celestrak.org/NORAD/archives/request.php?FORMAT=xml), preserve the returned file and request/capture date with a checksum and the stated terms, then pin a reviewed snapshot or query an authorized reproducible archive. A current GP query must never be substituted for an earlier epoch.

## Space-Track permission and query audit

In the [“Redistribution of Basic SSA Information” section of Space-Track's documentation](https://www.space-track.org/documentation), the operative clause grants “express blanket approval for transfer/redistribution of basic SSA data and services ... conditioned on appropriate citation.” The next sentence separately requires citations for published analyses. The documentation explicitly defines basic SSA data as TLEs, OMMs, SATCAT, and decay/reentry data. Thus it covers redistribution of raw **basic** elements, including historical GP sets accessed through Space-Track, subject to attribution; it does not on its face grant redistribution of advanced products, third-party observer elements, or every service available to an account. Access still requires a valid account. The same documentation's API guidelines direct users to retrieve GP_HISTORY for an object's history once, retain the result locally, and use bundled yearly files for large ranges. The redistribution clause does not waive those query limits. We found no separate bulk-publication prohibition for basic elements in that section, but anyone planning substantial raw-data republication should confirm current account terms and source lineage with Space-Track.

Space-Track documents `gp_history` and its `norad_cat_id` filter. Its schema includes `EPOCH` and `GP_ID`. Our E-002 subset preserves an epoch and TLE lines but no verified Space-Track `GP_ID`, so we cannot construct or validate an exact element-set permalink. A date-window query of the form `https://www.space-track.org/basicspacedata/query/class/gp_history/norad_cat_id/44797/EPOCH/2019-12-31--2020-01-01/format/xml` returned HTTP 401 when tested without credentials on November 15, 2026, as expected for an authenticated query. The same date-window pattern is linked for verified Space-Track E-002 elements, with the selected NORAD ID and UTC date. It may return several sets; it is **not** represented as an exact match. E-001's unlabeled historical sets remain “Source unverified”; their similarity to a Space-Track catalog record is not sufficient provenance evidence.
